Preference Tuning: RLHF and DPO

18 min read 5 sections Draft

15.1Preference Fine-Tuning

Preference fine-tuning is a way to train a model not just to imitate text, but to align with what humans prefer. Collect preference pairs and train the model on them.

Instead of learning: “What is the most likely next word?”

The model learns: “Which response is better according to humans?”

This is critical because:

  • Many answers can be grammatically correct

  • But only some are helpful, safe, honest, or polite

Why normal supervised fine-tuning (SFT) is not enough

SFT uses a prompt and an ideal answer as input

But humans often

  • Disagree on the “ideal” answer

  • Can rank answers more easily than write perfect ones

So we shift from absolute labels → relative preferences

15.2Preference Data

Observation = (prompt X, response ŷ)
But preference learning needs comparisons, not isolated answers.

A. Pointwise Scoring

Humans score each response independently.

Example Prompt: “Explain overfitting”

Responses

  • A → score = 4/5

  • B → score = 2/5

  • C → score = 5/5

How it works

  • Train a model to predict numeric scores

  • Treat as regression

Problems

  • Humans are inconsistent with scales

  • “4” for one annotator ≠ “4” for another

B. Pairwise Comparison (Most Common)

Humans compare two responses and choose the better one.

Step-by-step pipeline

  1. Take a prompt

  2. Sample multiple outputs from the model

  3. Show 2 outputs at a time to a human

  4. Ask:“Which response is better?”

Example Prompt: “How does gradient descent work?”

Model outputs: y₁, y₂, y₃, y₄

Create pairs: (y₁, y₂), (y₁, y₃), (y₂, y₄), ...

Humans select a winner for each pair. This creates a preference dataset.

C. Listwise Ranking

Humans rank N responses at once.

Example B > A > D > C

More informative, but

  • Expensive

  • Harder to annotate consistently

15.3Reinforcement Learning from Human Feedback (RLHF)

15.3.1Reinforcement Learning

Reinforcement Learning (RL) is a type of machine learning where an agent learns by interacting with an environment and receiving feedback in the form of rewards or penalties, with the goal of learning a policy that maximizes cumulative (long-term) reward.

Reinforcement Learning is the problem of learning a policy π(a∣s)that maps states s to actions a, so as to maximize the expected return:

Gt​=k=0∑∞​γkrt+k+1​
where

  • rt​= reward at time t

  • γ∈[0,1]= discount factor (importance of future rewards)

Core components of RL

  • Agent: the learner/decision-maker

  • Environment: the world the agent interacts with

  • State (s): current situation of the environment

  • Action (a): choice made by the agent

  • Reward (r): scalar feedback signal

  • Policy (π): strategy for choosing actions

  • Value function (V, Q): expected future reward

  • Return: total accumulated reward over time

15.3.2Reinforcement Learning for an LLM (RLHF)

Reinforcement learning with human feedback (RLHF) is a technique where AI improves by learning directly from human feedback. This way, you enrich AI's learning process with real human insights. In RLHF, AI doesn't just produce what it thinks is best based on data alone but also considers what people actually find useful or relevant. RLHF is especially handy for natural language processing tasks requiring a human touch, like creating content that genuinely resonates with us. By integrating our feedback, language models become more adept at delivering results that align with human goals and preferences, marking a significant step forward in generative AI applications, including large language models.

How does RLHF work

Picture this: you're fine-tuning a language model to summarize text.

Stage 1: Preference dataset

The process starts by giving the pre-trained model various prompts, such as requests to summarize specific texts like "The internet revolutionized how we share information, making it instant and accessible worldwide. It has become a crucial tool for communication, education, and entertainment."

Here model returns two different summaries of the same input text.

Summary 1: "The internet changed communication by making information sharing instant and global."

Summary 2: "The internet's impact includes transforming communication, enhancing education, and providing entertainment globally."

Human labelers evaluate pairs of model-generated responses to each prompt and select the more suitable option. This comparison builds our LLM evaluation or preference dataset.

Stage 2: Reward model

Next, we take the preference data we've gathered and get down to training a reward model.

To train a reward model, the comparison dataset should be in the format of (prompt, chosen response, rejected response ), i.e., the better option comes first.

Step1: Each training example looks like

(x,yi​,yj​)
where:

  • x= prompt

  • yi​= chosen / preferred response

  • yj​= rejected / less preferred response

Step2: The reward model is a neural network rθ​(⋅)that:

  • Takes prompt + response (concatenated) as input

  • Outputs one scalar number (reward)

Inputs to reward model

(x + y_i) → r_i
(x + y_j) → r_j

So we get

  • ri​=rθ​(x,yi​)

  • rj​=rθ​(x,yj​)

These are unbounded real numbers (not probabilities).

Step3: Bradley–Terry probability model

We now convert the two rewards into a preference probability.

Bradley-Terry formulation. The probability that response yi​is preferred over response yj​is:

P(yi​≻yj​)=eri​+erj​eri​​=σ(ri​−rj​)

where the sigmoid function is

σ(x)=1+e−x1​
where:

  • ri​is the reward (score) of the response yi​

  • rj​is the reward (score) of the response yj​

Step4: Intuition behind the probability

  • If ri​≫rj​→ probability ≈ 1

  • If ri​=rj​→ probability = 0.5

  • If ri​<rj​→ probability < 0.5

So: The model prefers the response with higher reward.

Step5: Loss function

Since humans say yi​it is better than yj​, we want: So we minimize the negative log-likelihood:

L=−logσ(ri​−rj​)​

This is the pairwise preference loss.

Step6: What this loss does to the rewards

During backpropagation

  • If ri​is too small → increase ri​

  • If rj​is too large → decrease rj​

So the model learns

ri​>rj​when humans prefer yi​
This model's job is essentially to act as the judge during the training process, scoring the LLM's responses using a reward function based on how well they align with what our human labelers prefer. This step turns qualitative judgments into quantifiable scores, offering a way to measure how close an LLM's response is to the ideal.

Stage 3: Fine-tuning using RLHF (Reinforcement Learning with Human Feedback) using ppo

The final step involves fine-tuning the base language model with the insights from the reward model. The aim here is to adjust the LLM's output to reflect human preferences better, as indicated by higher scores from the reward model.

Researchers (OpenAI, Anthropic, DeepMind) found a solution

  • Take a pretrained language model

  • Make a copy of it

  • Fine-tune the copy using a policy-gradient RL algorithm

  • Use Proximal Policy Optimization (PPO)

Training all parameters of a huge model is too expensive.

  • Freeze most parameters

  • Train only a small subset

  • Often done using LoRA (Low-Rank Adaptation)

Let’s define RL components clearly.

Policy

  • The language model

  • Input: prompt

  • Output: generated text or token probabilities

Action space

  • All possible tokens in the vocabulary

  • Usually ~50,000 tokens

State (observation space)

  • Prompt + tokens generated so far

  • Very large space:

vocab sizesequence length

From dataset: x = "A dog is..."

Step 2: RL policy generates text

This represents how much humans prefer this response. Interpretation: The response “A dog is man’s best friend” aligns 85% with human preferences.

Step 4: Compute KL penalty (policy shift constraint)

Kullback–Leibler (KL) divergence

KL divergence measures how different one probability distribution is from another.

In words: “How much did my new model’s behavior change compared to the old model?”

  • Small KL → behaves similarly

  • Large KL → behaves very differently

Token (yₜ) π₍RL₎(yₜ ∣ x, y₍ₜ₋₁₎) π₍base₎(yₜ ∣ x, y₍ₜ₋₁₎)
"man’s" 0.40 0.50
"best" 0.35 0.30
"friend" 0.25 0.20

We compare the RL model’s token probabilities with the base model’s probabilities for the same prompt. Using KL divergence:

rKL​=DKL​(πRL​(y∣x) ∥ πbase​(y∣x))

KL divergence is usually summed over all tokens, because probabilities are over sequences:

DKL​(πRL​∥πbase​)=t∑​πRL​(yt​∣x,y<t ​)logπbase​(yt​∣x,y<t ​)πRL​(yt​∣x,y<t ​)​

Plugging values in

DKL​=0.40log0.500.40​+0.35log0.300.35​+0.25log0.200.25​DKL​=0.40(−0.223)+0.35(0.154)+0.25(0.223)≈−0.089+0.054+0.056=0.021

So

rKL​=0.021
A KL divergence of rKL​=0.021is very small — meaning the new (RL) model’s behavior is very close to the base model’s behavior.

Without KL penalty

  • The model may learn to hack the reward

  • Produces nonsense text

  • Still gets a high reward from the reward model

KL penalty ensures: “Improve behavior without breaking language.”

Step 5: Update Rule

Final reward

r=rθ​−λrKL​

  • rθ​= human preference reward (Maximize rewards)

  • rKL​= KL penalty (Don't deviate too much from the base model)

  • λ= scaling factor

Let

  • rθ​=0.85

  • λ=5.0

  • rKL​=0.021

Then

r=0.85−5(0.021)=0.85−0.105=0.745
Final reward = 0.745

The advantage function is reward minus baseline (often value model). It reduces variance in policy gradients.

A=r−b​

  • b= baseline (value model or mean reward)

  • Reduces variance

Let baseline b=0.70(estimated average reward by a value model).

  • A=0.745−0.70=0.04

  • Advantage = 0.045

Policy Gradient Objective

J(θ)=E[t=1∑T​logπθ​(yt​∣x,y<t ​)⋅A]​

  • It increases the probability of tokens that led to a good outcome and decreases the probability of tokens that led to a bad outcome.

  • J(θ)is the Policy gradient objective function

  • It measures how good the model is

  • So: Higher J(θ)= better model behavior

Let’s compute for our 3 tokens

Token π₍RL₎ log(π₍RL₎) log(π₍RL₎) × A
"man's" 0.40 -0.916 -0.916 × 0.045 = -0.041
"best" 0.35 -1.050 -1.050 × 0.045 = -0.047
"friend" 0.25 -1.386 -1.386 × 0.045 = -0.062

  • Sum = −0.041−0.047−0.062=−0.15

  • So: J(θ)=−0.15

  • In gradient ascent, we want to maximize J(θ), so we move in the direction of increasing it.

update

∇θ​J(θ)=+0.045

  • This is the gradient of the objective with respect to the parameters

  • It tells us: In which direction should each parameter change to increase the reward?

  • Think of it as: A vector pointing uphill on the reward surface


θ←θ+∇θ​J(θ)

  • θrepresents all trainable parameters of the model (weights, biases, LoRA adapters, etc.)

  • In RLHF, most parameters are frozen, and only some of θthem are updated

  • Means: Replace the old parameters with new, improved ones

Update rule (with learning rate η = 0.01)

The model’s parameters are slightly nudged toward increasing the probability of producing similar outputs (“man’s best friend”) for similar prompts.

How PPO updates the model

  • PPO actually computes advantages (and not just rewards)

  • PPO maximizes the final reward

  • Updates parameters only using the current batch

  • PPO is on-policy

  • Uses trust-region constraints

  • Prevents large, unstable updates

15.3.3PPO-CLIP Adjustment (Extra Stability)

In PPO, instead of directly applying the gradient, the update is clipped to prevent large changes:

LCLIP(θ)=Et​[min(rt​(θ)At​,clip(rt​(θ),1−ϵ,1+ϵ)At​)]

where

rt​(θ)=πold​(yt​)πθ​(yt​)​

is the probability ratio between the new and old policies. and typically ϵ=0.2.

  • x-axis: r=rt​(θ)=πold​(yt​)πθ​(yt​)​

    • If r>1: new policy assigns higher probability to this action.

    • If r<1: new policy assigns lower probability.

  • y-axis: LCLIP, the clipped loss term that PPO maximizes.

Left Side (A > 0) — Good actions

  • When Advantage A > 0, the action was better than expected.

  • The model should increase its probability (r should rise).

  • But if r>1+ϵ, we stop increasing — that’s the “clip” limit.

  • This prevents the model from over-updating in one step.

  • The line rises until r=1+ϵ, then flattens.

Right Side (A < 0) — Bad actions

  • When Advantage A < 0, the action was worse than expected.

  • The model should decrease its probability (r should go down).

  • But if r<1−ϵ, we stop decreasing — another clip limit.

  • The line stays flat (no extra penalty) until r=1−ϵ, then declines linearly as r keeps dropping.

The Red Dot

The red dot marks the current r value — it shows where the model currently is relative to the clipping range. If it’s outside the [1−ε, 1+ε] region, the gradient is clipped (i.e., no stronger push in that direction).

PPO-Clip Intuition

  • If policy changes too much → clip

  • Prevents model from:

    • Exploiting reward model

    • Forgetting language ability

15.3.4PPO-KL Penalty

PPO-KL penalty is a combination of the PPO clipping objective and an explicit KL divergence term.
It ensures that the model learns from human-preferred responses without drifting too far from safe, fluent language behavior.

L(θ)=Ex,y∼πθ​​[min(rt​(θ)At​,clip(rt​(θ),1−ϵ,1+ϵ)At​)−λDKL​(πθ​(⋅∣x) ∥ πref​(⋅∣x))]​

15.3.5PPO Limitations

  • Requires training a reward model (2-stage process)

  • Many hyperparameters to tune

  • Training instability

  • Metric to monitor training

  • Need diversity in completions!

Not abundantly clear why preference tuning absolutely needs RL

15.4Best-of-N (BoN) — An RL-Free Alternative

Idea

  • Generate N candidate responses for a given prompt.

  • Use a reward model to score each response.

  • Select the highest-scoring response as the final output.

  • No learning or model updates — purely inference-time selection.

Pros

  • Simple to implement — no RL loops or gradient updates needed.

  • Stable — avoids RL instabilities and tuning difficulties.

  • Can improve output quality using existing reward models.

Cons

  • Expensive at inference — generating and scoring multiple responses increases compute and latency.

  • Doesn’t improve the model for future prompts — only selects the best from the current batch.

15.5DPO: Direct Preference Optimization (Supervised Alternative)

Direct Preference Optimization (DPO) is an alternative to RLHF that learns directly from human preference data without using reinforcement learning or policy gradients.

The key idea: instead of learning a reward model and then using RL to maximize it (like PPO in RLHF), DPO directly trains the model to prefer outputs that humans like.

Suppose we have

  • A prompt x

  • Two candidate responses:

    • y+: human-preferred response

    • y−: human-disliked response

DPO aims to adjust the model so that the probability of the preferred response is higher than the probability of the non-preferred response:

Pθ​(y+∣x)>Pθ​(y−∣x)

DPO Loss Function (Mathematical Formulation)

LDPO​(πθ​;πref​)=−E(x,yw​,yl​)∼D​[log⁡σ(β(logπref​(yw​∣x)πθ​(yw​∣x)​−logπref​(yl​∣x)πθ​(yl​∣x)​))]​

Symbol Meaning
x
 Prompt
yw​
 Preferred (winning) response chosen by humans
yl​
 Disliked (losing) response
πθ​
 The current trainable policy/model
πref​
 The reference model (usually the original base model)
β
 Temperature scaling factor controlling preference sharpness
σ(z)=1+e−z1​
 Logistic sigmoid function
D
 Dataset of human preference pairs (x,yw​,yl​)

Intuition

  • The model compares how much more likely the preferred response is relative to the reference model, versus the disliked response.

  • If the model increases the probability of the preferred output relative to the reference, the loss decreases.

  • This formulation implicitly regularizes the model using πref​, so it doesn’t deviate too far — similar to KL control in RLHF.

Token-Level Decomposition

Since LLMs generate sequences, the probability of a sequence yis:

πθ​(y∣x)=t=1∏T​πθ​(yt​∣x,y<t ​)

So DPO effectively encourages

t∑​logπθ​(ywt​∣x,yw<t ​)>t∑​logπθ​(ylt​∣x,yl<t ​)

relative to the same ratio under πref​.

15.5.1Numerical Example

Let’s make a toy example with a single prompt

  • Prompt: x="A dog is…"

  • Preferred response: yw​=“man’s best friend”

  • Non-preferred: yl​="a loud animal"

Step 1: Assign model probabilities (token-wise)

Token πₜₕ(y_w) π_ref(y_w) πₜₕ(y_l) π_ref(y_l)
Token 1 0.40 0.45 0.30 0.40
Token 2 0.35 0.30 0.20 0.30
Token 3 0.25 0.25 0.10 0.20

Sequence probabilities (product of tokens)

πθ​(yw​∣x)=0.40⋅0.35⋅0.25=0.035πref​(yw​∣x)=0.45⋅0.30⋅0.25=0.03375πθ​(yl​∣x)=0.30⋅0.20⋅0.10=0.006πref​(yl​∣x)=0.40⋅0.30⋅0.20=0.024

Step 2: Compute log ratio

logπref​(yw​∣x)πθ​(yw​∣x)​=log0.033750.035​=log(1.036)=0.035logπref​(yl​∣x)πθ​(yl​∣x)​=log0.0240.006​=log(0.25)=−1.386

Step 3: Compute preference score

Let β=1:

Δ=β[0.035−(−1.386)]=1.421

Step 4: Apply sigmoid

σ(Δ)=1+e−1.4211​=0.806

Step 4: Compute DPO loss

LDPO​=−log(σ(Δ))=−log(0.806)=0.216

Low loss means the model correctly prefers the human-preferred output relative to the reference. If the disliked output had higher probability, the loss would increase — pushing gradients to favor the preferred response.

15.5.2Key Advantages of DPO

  • No RL or policy gradients → simpler and more stable training.

  • Directly uses human preference pairs.

  • Fully differentiable → can use standard optimizers (Adam, etc.).

  • Can achieve results comparable to RLHF but with less computational overhead.

  • DPO removes RL entirely.
