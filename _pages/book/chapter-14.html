Training, Scaling and Optimizing LLMs

9 min read 11 sections Draft

14.1LLM Objective Function

An LLM is trained using a maximum likelihood objective that minimizes cross-entropy loss for predicting the next token conditioned on all previous tokens.

For a sequence of tokens:

(x1​,x2​,…,xT​)
The model maximizes:

t=1∑T​logP(xt​∣x1​,…,xt−1​)
This is called Maximum Likelihood Estimation (MLE).

Loss function (Cross-Entropy)

L=−logP(xt​∣context)
Penalizes the model when it assigns low probability to the true next token.

14.2FLOPs vs FLOP/s

FLOPs measure the total number of floating-point calculations a model performs.

  • What it tells you: how much computing work is required

  • Used for: estimating training or inference cost

  • Example: training a large LLM may require ~10²³ FLOPs

FLOP/s (or TFLOP/s) measures how fast hardware performs those operations.

  • Speed of computation

  • Example:

    • GPU = 100 TFLOP/s

    • Meaning: 10¹⁴ operations per second

14.3Chinchilla Scaling Law

For a fixed compute budget, LLM performance is best when model size and training data are balanced, not when the model is as large as possible.

Key result (DeepMind, Chinchilla): Training tokens≈20×number of parameters

Meaning

  • Earlier models were too large and trained on too little data

  • Smaller models trained on more data perform better for the same FLOPs

Impact

  • Changed how modern LLMs are trained (GPT-4, LLaMA, Gemini)

  • Shifted focus from “bigger models” to data + compute balance

14.4Learned Knowledge Challenges

Learned knowledge

  • Knowledge is embedded in weights

  • Not stored as explicit facts

Knowledge cutoff

  • The model only knows the data before training date

  • Cannot update without retraining

Hard to edit knowledge

  • Cannot easily remove one fact

  • Editing requires finetuning or retraining

Plagiarism risk

  • The model may memorize the training text

  • Especially with rare phrases

14.5Data Parallelism (DP)

Data Parallelism is a training strategy where the same model is replicated on multiple GPUs, and each GPU processes a different subset of the training data in parallel.

How it works

  • Each GPU has a full copy of the model

  • The training batch is split across GPUs

  • Each GPU computes gradients on its data

  • Gradients are averaged (all-reduce)

  • All model copies are updated identically

Example

  • Batch size = 1024

  • GPUs = 4

  • Each GPU processes 256 samples

Benefits

  • Simple to implement

  • Scales well for large datasets

Limitation

  • High memory usage: model weights, gradients, and optimizer states are duplicated on every GPU

Parallelism Variations

  • Tensor Parallelism (TP)

  • Pipeline Parallelism (PP)

  • Sequence Parallelism (SP)

  • Context Parallelism (CP)

  • Expert Parallelism (EP)

14.6ZeRO – Zero Redundancy Optimization

ZeRO is a data-parallel training optimization that removes memory duplication by sharing model states across GPUs instead of replicating them.

In standard Data Parallelism, each GPU stores:

  • Model parameters

  • Gradients

  • Optimizer states

This causes huge memory redundancy. So in ZeRO, each GPU stores only a fraction of the model states and reconstructs what it needs on demand.

ZeRO-1

  • Shared optimizer states

  • Parameters and gradients are still replicated

ZeRO-2

  • Shared optimizer states + gradients

  • Parameters still replicated

  • Memory saved: optimizer + gradients

ZeRO-3

  • Shared optimizer states + gradients + parameters

  • No full model copy on any single GPU

14.7Flash Attention (Major Optimization)

Standard Self-Attention

softmax(d​QKT​)V
Problem

  • Standard attention keeps writing and reading a huge attention matrix to HBM.

  • Memory-bound

Note: HBM (High Bandwidth Memory) is the main GPU memory used to store large tensors such as model weights, activations and attention matrices

Flash Attention is an optimized attention algorithm that reduces slow GPU memory (HBM) access by computing attention in small blocks that fit in fast on-chip memory (SRAM), instead of storing large intermediate matrices.

HBM = large but slow GPU memory

SRAM = very small but very fast memory inside the GPU

What Flash Attention does

  1. Minimize HBM reads/writes

  • Avoid storing the full attention matrix in GPU memory.

  1. Use tiling

  • Tiling means cutting a large matrix into small pieces (tiles).

  1. Load small blocks into SRAM

  • Each tile is small enough to fit in fast SRAM.

  1. Compute attention block-by-block

  • Compute softmax and value multiplication immediately

  • Then discard the tile and move to the next one

Recompute instead of storing

  • Don’t store attention matrix

  • Recompute partial results on the fly

14.8Precision & Mixed Precision Training

Precision refers to how many bits are used to represent numbers during model training (for example, 32-bit or 16-bit).

  • FP32: high accuracy, slow, high memory

  • FP16 / BF16: lower precision, faster, less memory

Mixed precision training uses both high and low precision together—low precision for most computations and high precision where accuracy is critical.

Example:

  • Forward & backward pass → FP16 / BF16

  • Weight updates → FP32

Why they are used

  • Faster training (better GPU utilization)

  • Lower memory usage

  • Larger models or batch sizes fit on GPUs

  • Minimal loss in accuracy when done correctly

14.9Fine-Tuning Large Language Models

14.9.1Supervised Finetuning (SFT)

Supervised Fine-Tuning (SFT) is the process of training a pretrained language model on labeled input–output examples so it learns to produce desired responses.

How it works

  • Start with a pretrained LLM

  • Use a dataset of (prompt → correct answer) pairs

  • Train using standard cross-entropy loss

  • Model learns to imitate high-quality responses

Example

Prompt: “Explain photosynthesis”

Target output: “Photosynthesis is the process by which plants use sunlight…”

The model is trained to predict the target response token-by-token.

Why SFT is used

  • Aligns the model with human-written answers

  • Improves instruction-following

  • Makes outputs more helpful and structured

Limitations

  • Requires very high-quality labeled data

  • Sensitive to the prompt style

  • Can overfit to training patterns

14.9.2Instruction Tuning

Instruction tuning is a form of fine-tuning where a pretrained language model is trained on many tasks written as natural-language instructions, so it learns to follow instructions rather than just complete text.

How it works

  • Model take input + instruction and produce response

  • Train the model using supervised learning

  • Model learns to generalize across instructions

Example

Instruction: “Summarize the following paragraph in one sentence.”

Input: (long paragraph)

Response: (short summary)

The model is trained to produce the response given the instruction.

Why it is it used

  • Improves zero-shot and few-shot performance

  • Makes the model more general-purpose

  • Better alignment with how humans ask questions

Challenges

  • Requires very high-quality data

  • Sensitive to prompt style

  • Hard to evaluate

  • Expensive

Benchmarks

Capability Benchmark
General knowledge MMLU
Reasoning ARC-Challenge
Math GSM8K
Code HumanEval

Real-life evaluation

  • Chatbot Arena

  • A/B testing user prompts

14.10Parameter-Efficient Fine-Tuning (PEFT)

14.10.1Parameter-Efficient Finetuning (LoRA)

Fine-tuning a large LLM normally means updating all model weights, storing a full copy per task, and a huge memory + compute cost

Example:

  • 7B model in FP16 ≈ 14 GB

  • Fine-tuning for 10 tasks → 140 GB

LoRA (Low-Rank Adaptation) fine-tunes a model by freezing original weights and learning small, low-rank matrices that modify the model’s behavior.

What LoRA changes (big idea)

LoRA says: “Don’t change the big weight matrix directly.
Instead, add a small, smart correction.”

Step 0: Original Linear Layer (baseline)

You have a weight matrix:

W∈R1000×1000

This means:

  • Input size = 1000

  • Output size = 1000

Number of parameters

1000×1000=1,000,000

Step 1: Normal fine-tuning (what we avoid)

In full fine-tuning:

W→W+ΔW
Where:

ΔW∈R1000×1000
You must learn 1,000,000 new values

Step 2: LoRA restriction (key idea)

LoRA forces the update to be:

ΔW=BA
Shapes must match

BA∈R1000×1000

So we choose:

A∈Rr×1000B∈R1000×r

Step 3: What is r? (very important)

r=rank

Rank = number of independent directions a matrix can move or affect; low-rank means it only changes a few directions, not everything. The update can only affect 4 independent directions in the 1000-dimensional space, instead of changing everything

  • Controls how expressive the update is

  • Small r= small, efficient change

  • Always:

r≪1000
In this example

r=4

Step 4: Actual matrix sizes (plug in numbers)

A∈R4×1000B∈R1000×4

Step 5: Parameter count (math)

Matrix A

4×1000=4,000

Matrix B

1000×4=4,000

Total LoRA parameters

4,000+4,000=8,000

Step 6: Compare with full fine-tuning

Method Trainable parameters
Full fine-tuning 1,000,000
LoRA (r = 4) 8,000

1,000,0008,000​=0.8%
Over 100× fewer parameters

Step 7: How this appears in the forward pass

Normal layer

y=Wx

With LoRA

y=Wx+BAx

Where LoRA is applied

  • Q, K, V projections

  • FFN layers

  • LoRA needs a higher learning rate than full fine-tuning

  • LoRA does poorly on large batch size compared to full fine-tuning

Aspect Full FT LoRA
Trainable params 100% <1%
Memory Huge Small
Task switching Hard Easy
Catastrophic forgetting Yes No

14.10.2QLoRA (LoRA + Quantization)

Quantization is the process of converting numbers (weights or activations) in a neural network from high-precision (like 32-bit or 16-bit floats) to lower-precision numbers (like 8-bit, 4-bit, or integers) to save memory and speed up computation.

QLoRA is a method to fine-tune very large LLMs efficiently by combining:

  • Quantization of the base model → reduces memory and compute

  • LoRA adapters → train a small number of parameters on top

Step 1: Quantize the base model

  • Base model weights (W) are originally 16-bit or 32-bit floats → high memory

  • Quantization reduces them to 4-bit → huge memory savings

Formula (simplified):

Wquant​=Quantize(W,4-bit)
Model can now fit much larger LLMs on small GPUs

Step 2: Train LoRA adapters in higher precision

  • LoRA matrices A and Bare still 16-bit or 32-bit

  • This ensures training stability and precision for task-specific updates

Forward pass example:

y=W4-bit​x+BAx

NF4 (NormalFloat 4-bit)

NF4 is a special 4-bit floating-point format used for quantization.

  • Unlike regular 4-bit, NF4 distributes numbers according to a normal distribution

  • Preserves small and large weight values more accurately

  • Less information loss → better model performance

14.11Quantization Types

Single Quantization

  • Quantize weights once (e.g., from FP16 → 4-bit NF4)

  • Memory use is reduced

  • Faster inference and training

Example:

WFP16​→QuantizeWNF4​

Double Quantization

  • Not only are weights quantized, but the quantization constants themselves are also quantized

  • Further reduces memory usage

  • Slight trade-off in precision

Example:

  • Normally quantization uses scale factors:

Wq​=round(sW​),s=scale factor

  • Double quantization → store s itself in 4-bit instead of full precision

  • Benefit: Fits very large models (70B+) on a single GPU or small clusters)

Why is used

  • Reduce memory usage → fit larger models on smaller GPUs

  • Faster computation → less data to move around

  • Enable efficient fine-tuning → like QLoRA, you can train LoRA adapters on 4-bit base models

Intuition / Analogy

  • Think of base model as a huge library of books:

    • Quantization = shrink each book into 4 pages instead of 16

    • LoRA = sticky notes you add with task-specific notes

  • NF4 = smart shrinking that keeps the main content readable

  • Double quantization = shrink even the sticky notes’ labels
